---
title: Private DNS
description: Reach every device as <name>.internal.
---

Every device resolves as `<name>.internal`, e.g. `ssh jabeds-macbook-air.internal`.
Device names come from the hostname (lowercased, first label) and are unique
in the network: a second `laptop` becomes `laptop-2`. Mesh addresses resolve
back to names too (`dig -x 10.77.0.214`).

## Renaming and removing devices

Owners and admins can rename a device on its network page. Peers resolve the
new name, and the device saves it, within one sync (~10s). The old name stops
resolving.

Owners and admins can also remove a device there. Peers drop it on their next
sync, and its agent is refused from then on. To bring it back, run
`meshguard logout --force` on it, then `meshguard up --token <new token>`.

## How it resolves

The agent answers DNS at `100.100.100.53` on every device. Queries to it are
routed into the WireGuard interface and answered by the agent itself; they
never leave the machine. The OS sends only `.internal` and the mesh's reverse
zones there; other lookups never touch it.

| Platform | Setup |
| --- | --- |
| macOS | Writes `/etc/resolver/internal` and one file per reverse zone (removed on `meshguard down`). Short names don't resolve. |
| Linux with systemd-resolved | `resolvectl dns/domain` on `meshguard0`. `internal` is a search domain, so short names work: `ssh laptop`. |
| Other Linux | The OS isn't configured. Query the resolver directly: `dig @100.100.100.53 laptop.internal`. |
